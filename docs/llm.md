# Applet-owned LLM history

Apell owns model access, credentials, transport, cancellation, and attribution. The applet owns the complete message history, context selection, tools, validation, review, and persistence. Apell does not store conversation history or continuation state.

`llm.generate(request, options)` returns the authoritative outcome. `options.on_event` receives progress only; `options.signal` cancels the native request. Request IDs are generated by the SDK unless supplied explicitly. `completed` is a finished answer; `tool_calls` hands control to the applet. Other statuses preserve partial answer text without providing a replayable message. A bridge failure can reject the promise with `HostError`, including any answer text received before the connection failed.

On success, save and append `result.message` unchanged. It contains the complete assistant message, including any provider-specific reasoning fields or other replay metadata. Do not reconstruct it from the display text or normalized `result.tool_calls`. The applet decides whether and how to persist this data; storing the complete message can retain reasoning even when the UI shows reasoning only temporarily. No credentials are included by Apell.

Messages currently use the text Chat Completions shape: `role`, string or null `content`, optional raw `tool_calls`, `tool_call_id`, and additional JSON fields. Raw calls have `{ id, type: 'function', function: { name, arguments } }`; `result.tool_calls` is a normalized convenience view for execution. Extra fields stay attached to their original messages. There is no opaque host handle or session-bound cache to expire after reopening an applet.

```ts
import {
  llm,
  type LlmEvent,
  type LlmMessage,
  type LlmTool,
} from '../../../packages/applet-sdk/src';

const tools: LlmTool[] = [
  {
    name: 'propose_annotation',
    description: 'Propose an annotation draft for user review.',
    parameters: {
      type: 'object',
      properties: { text: { type: 'string' } },
      required: ['text'],
      additionalProperties: false,
    },
  },
];
const messages: LlmMessage[] = [
  { role: 'system', content: 'Answer the question and propose a draft when useful.' },
  { role: 'user', content: selectedPassageAndQuestion },
];
const controller = new AbortController();
// Connect a Stop button to controller.abort().
const options = {
  signal: controller.signal,
  on_event: (event: LlmEvent) => {
    if (event.kind === 'text_delta') showAnswerDelta(event.text);
    if (event.kind === 'reasoning_delta') showTransientReasoning(event.text);
  },
};

try {
  const result = await llm.generate({ messages, tools, tool_choice: 'auto' }, options);
  if (result.status === 'completed' && result.message) {
    messages.push(result.message);
    showCompletedAnswer(result.content, result.provenance);
  } else if (result.status === 'tool_calls' && result.message) {
    messages.push(result.message);
    for (const call of result.tool_calls) {
      let outcome: { accepted: boolean; reason?: string };
      try {
        if (call.name !== 'propose_annotation') throw new Error('Unknown tool');
        const draft = validateDraft(JSON.parse(call.arguments));
        showDraftForReview(draft, result.provenance);
        outcome = { accepted: true };
      } catch {
        outcome = { accepted: false, reason: 'The proposed draft did not pass validation.' };
      }
      messages.push({ role: 'tool', tool_call_id: call.id, content: JSON.stringify(outcome) });
    }
    const next = await llm.generate({ messages, tools, tool_choice: 'none' }, options);
    if (next.status === 'completed' && next.message) {
      messages.push(next.message);
      showCompletedAnswer(next.content, next.provenance);
    } else {
      showInterruptedAnswer(next.content, next.status, next.error);
    }
  } else {
    showInterruptedAnswer(result.content, result.status, result.error);
  }
} catch (error) {
  showHostFailure(error);
} finally {
  clearTransientReasoning();
}
```

The application functions above validate and present a draft; they do not save an annotation automatically. Persist model attribution from each result's `provenance`, preserving a missing actual `model_id` as unknown. The applet also decides whether saved history can be reused with a different configured connection or model; Apell does not manage a conversation target or silently adapt provider-specific metadata.

Streaming is enabled by default. Use `stream: false` for a complete buffered response when a provider's structured metadata cannot be assembled safely from deltas. Buffered assistant metadata is returned intact. Unsupported stream metadata produces an explicit `unsupported` result; Apell does not silently discard it or automatically repeat a generation. Optional `max_output_tokens` maps to the compatible endpoint's `max_tokens` field.

This contract intentionally replaces the earlier completion API. Rebuild applets against the current SDK; `llm.complete`, global LLM event subscriptions, and continuation IDs are removed.
